# Penny-Wise Tracker

A React + TypeScript + MUI expense tracker. Transactions continue to work with browser localStorage when Supabase is not configured. When Supabase credentials are configured, the app loads, adds, and deletes records in the cloud.

## Run the project

1. Extract this ZIP and open the project folder in VS Code.
2. Install dependencies: `npm install`
3. Copy `.env.example` to a new file named `.env` in the project root.
4. If you want cloud storage, fill in the Supabase values below. If not, leave `.env` absent and the app uses localStorage.
5. Start the site: `npm run dev`. For a production check, run `npm run build`.

## Supabase setup (beginner steps)

1. Visit https://supabase.com and create an account, then create a new project. Save the database password somewhere safe; the app does not need that password.
2. In your Supabase project, open **SQL Editor**, create a new query, paste and run this SQL:

   ```sql
   create table if not exists public.transactions (
     id bigint generated by default as identity primary key,
     title text not null,
     amount numeric not null check (amount > 0),
     category text not null,
     type text not null check (type in ('income', 'expense')),
     date date not null
   );

   alter table public.transactions enable row level security;

   create policy "Allow app access to transactions"
   on public.transactions for all
   to anon
   using (true)
   with check (true);
   ```

   **Security note:** this simple policy allows anyone who has your project URL and publishable/anon key to read/change this table. It is suitable only for a personal learning demo with no sensitive data. Before using real financial information or publishing the app, add Supabase Auth and user-based policies (for example, a `user_id` column and policies that only allow each signed-in user to access their own rows). Never put the `service_role` or secret key in frontend code.
3. Open **Project Settings → API** (or **Connect**) and copy the Project URL and the publishable/anon key. These are the public client credentials; do not copy a secret/service-role key.
4. In the project root, copy `.env.example` to `.env` and set:
   ```env
   VITE_SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
   VITE_SUPABASE_ANON_KEY=YOUR_PUBLISHABLE_OR_ANON_KEY
   ```
5. Stop and restart `npm run dev` after changing `.env`. Do not commit `.env` to Git. Vite variables beginning with `VITE_` are visible in the browser, so only use the publishable/anon key with proper Row Level Security.
6. On first load, the app fetches cloud records and imports localStorage-only records if an equivalent record is not already in the database. A match is based on title, amount, category, type, and date. Review the imported rows in the Supabase Table Editor.

## What was updated

- Transactions filters: date (shown first), category, search, and Income/Expense type work together.
- Transactions are sorted newest date first.
- Activity is grouped under Today, Yesterday, or a formatted date on the Dashboard and Transactions page.
- Added a category expense pie chart based on actual expense amounts; income is excluded and empty data is handled.
- Add Transaction keeps React Hook Form and reports cloud-save failures with Toastify.
- React Context keeps localStorage persistence and uses Supabase when `.env` credentials are configured.
- Delete confirmation remains in place and reports errors if a cloud delete fails.

## How the main pieces work

- `TransactionList.tsx` filters the store array, sorts by date, then places a date heading before the first transaction of each date.
- `Transactions.tsx` totals only `expense` records by category. The percentage is category amount divided by all expenses, and the circular chart uses those percentages.
- `expenseStore.js` is the shared source for add/delete/load operations. Without Supabase settings it uses the existing localStorage-backed React Context store.
- `AddTransactionDialog.tsx` uses React Hook Form's registered `type` field. The selected `income` or `expense` value is sent to the store and used by the totals and list styles.

## Important limitations

- The SQL policy above is intentionally permissive for a demo. Do not store real/private financial data until authentication and user-specific RLS policies are added.
- Cloud migration uses matching field values to avoid importing duplicate local records; two genuinely separate transactions with identical title, amount, category, type, and date are treated as a match during initial migration.
- Build verification could not complete in this environment because dependencies were not installed before the install command timed out. Run `npm install` and `npm run build` locally to verify.


## State management note

This version does not use Zustand. Supabase is the database that permanently stores transactions online. A small React Context provider keeps the latest database results available to the Dashboard, Summary Cards, Add Transaction dialog, and Transactions page while the app is open. These are different jobs: Supabase stores data; React Context shares the loaded data between components.

## Expense pie chart

The category pie chart uses the official MUI X Charts `PieChart` component from `@mui/x-charts`. It uses expense totals grouped by category, excludes income, and calculates each slice label as a percentage of total expenses. If there are no expenses, the chart is hidden and an explanatory message is shown.
